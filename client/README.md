# ContractGuard AI

ContractGuard AI is a planned local-first developer tool for detecting probable contract drift between OpenAPI-defined REST APIs and JavaScript/TypeScript consumers.

## The Problem

REST API changes can silently break consumer applications when endpoints, HTTP methods, required parameters, request schemas, or response properties change. Reviewing an API specification and consumer code manually is difficult and error-prone, especially when the provider and consumer evolve separately.

## What ContractGuard AI Does

The planned MVP follows this workflow:

**OpenAPI Contract -> JS/TS Consumer Analysis -> Contract Comparison -> Findings -> Human Review**

It is intended to parse an OpenAPI 3.x contract, identify detectable REST API usage in JavaScript/TypeScript consumer code, compare the two sources, and present probable integration risks with supporting evidence. Optional local Ollama assistance may make findings easier to understand. Deterministic evidence and human engineering judgment remain authoritative.

## MVP Scope

### In Scope

The following capabilities are planned for the MVP:

- OpenAPI 3.x REST API processing.
- JavaScript/TypeScript consumer analysis.
- Common `fetch` patterns and supported `axios` patterns.
- Endpoint, HTTP-method, parameter, request-schema, and response-schema comparison where statically observable.
- Evidence-based findings for developer review.
- Optional analysis of a selected GitHub repository.
- Optional explanations generated by a locally running Ollama model.
- Local-first execution suitable for a focused university-project demonstration.

### Out of Scope

- GraphQL, gRPC, SOAP, WebSocket, and event-stream contracts.
- Consumer analysis for Python, Java, C#, Go, or other non-JavaScript/TypeScript languages.
- General vulnerability scanning.
- Fully autonomous source-code modification.
- Automatic production deployment or merging.
- Enterprise-scale governance and hosted-service operation.
- A cloud AI dependency.

## Key Features

### Implemented

No executable ContractGuard AI capabilities are implemented in the repository yet. The repository currently contains project documentation only; there is no application source code, package manifest, dependency configuration, or verified development command.

### Planned MVP

- OpenAPI contract validation and extraction.
- Detection of statically recognizable `fetch` and `axios` usage.
- Comparison of provider contracts with consumer expectations.
- Probable mismatch detection with traceable evidence.
- Findings presentation for human review.
- Optional local Ollama explanations.
- Optional GitHub repository input.

## How It Works

The intended workflow is:

1. Provide or select an OpenAPI 3.x specification.
2. Select local JavaScript/TypeScript consumer code or an available GitHub repository.
3. Extract statically recognizable REST API usage.
4. Compare consumer usage with the provider contract.
5. Produce evidence-based findings for probable mismatches.
6. Optionally request a plain-language explanation from local Ollama.
7. Review the evidence and make the final engineering decision.

This workflow is planned; it is not currently runnable from this repository.

## Finding Types

The planned MVP may report findings such as:

- Missing endpoint.
- HTTP method mismatch.
- Parameter mismatch.
- Request-schema mismatch.
- Response-schema or response-property mismatch.

These are probable integration risks, not absolute proof of a defect. Static analysis may miss highly dynamic JavaScript behavior and may produce false positives.

## AI Assistance

ContractGuard AI may use a locally running Ollama model to turn deterministic findings into clearer explanations and review guidance.

> **AI output is advisory only. Deterministic evidence and human engineering judgment remain authoritative.**

Ollama assistance is optional and must not be treated as an independent decision-maker or as a cloud AI requirement.

## Limitations

- Static analysis cannot reliably resolve every dynamic JavaScript/TypeScript pattern.
- Some API calls may be missed, and findings may contain false positives.
- Initial consumer support is limited to JavaScript/TypeScript.
- Initial contract support is limited to OpenAPI 3.x REST APIs.
- AI explanations may be incorrect.
- Every finding requires developer review.
